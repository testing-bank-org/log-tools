LOG ANALYZER

Multi-Product Log Search — No Server, No Network

1. Click Choose Folder… below and pick a log folder — APIMS's routelog*.json files (e.g. the folder containing Node1/Node2), the Bakong Processor's logs/log-*.txt files, MBS's own local *__Ex_*.log/*__App_*.log files, or any mix at once. Each file's format is detected automatically — or just drag the files/folders straight onto this page.
2. Everything is parsed in your browser only — nothing is uploaded anywhere, safe for logs with customer data, tokens, etc.
3. Search has three modes, picked with the buttons beside the box: All words (the default) needs every keyword to appear somewhere in the entry, in any order — bakong 500 rid-00136 finds entries containing all three, wherever each one appears; Any word matches an entry containing at least one of them, for widening a hunt (timeout refused reset); Exact stops splitting altogether and looks for the whole query as one literal string, spaces and punctuation included — this is the one for “how many invalid signature errors today”, because All words would also count rows where invalid and signature merely both appear. Typing the quotes is fine: "invalid signature" and invalid signature mean the same thing in Exact. A phrase is only ever found inside a single field, never spanning two columns. Your choice is remembered, and when All words is over-counting, the line under the keywords tells you how many contain the phrase and offers the switch. It searches the full body of every entry plus the route, status, level and RequestId, not just what's on screen. Wrap words in quotes to keep them together: "insufficient balance". The box wraps and grows so you can always read back the whole query, and when you use more than one keyword each is listed underneath with how many rows contain it on its own — so a typo shows up as tmeout 0 instead of silently emptying the table.
4. Use the Product/Route dropdowns and the Slow/Errors presets to triage fast — click a row afterward for the full request/response (or full log entry) and, for APIMS, the T24-internal timing breakdown. Everything currently narrowing the view shows up as a removable chip under the filters.
5. Time range: drag across the timeline to select a window — the bars show entries over time with errors in red, so the spike is usually the thing you're looking for. Double-click it to clear. The From/To boxes are plain text: paste a timestamp straight out of a log line — or paste the whole line, it will find the timestamp — in any format these logs use (2026-08-19T20:23:34.5033986+07:00, 2026-08-19 20:23:34.503, [2026-08-19 20:23:34.503]). Partial values work too: 2026-08-19 means that whole day, 20:23 means that minute on the last day in your logs, and -2h means the last two hours of the logs, not of right now. Arrow keys nudge a value by a minute (Shift = hour, Alt = second). Times without an explicit offset are read as +07:00, matching the Time column, and the box underneath always echoes back exactly how it was understood.
6. Rows are sorted slowest-first by default — click any column header to re-sort. Rows with no measurable response time (most Bakong Processor and MBS App Log entries — they're single log statements, not request/response pairs) sort to the bottom and show "—" instead of a time.
7. Working across several tabs: name each tab in the bar at the very top (a ticket number works well) — the name, the folder it loaded and the row count all go into the browser tab title and the favicon, so you can tell a row of these apart at a glance. The bar also always says which folders this tab read and when; click files to see exactly which files. copy range / paste range move a time window between tabs and between this and the MBS analyzer in one click.
8. Export settings (top bar) sets the file name from a template — {label}, {from}, {rows} and so on — and where exports go: your downloads, a Save as… dialog that opens in the folder you used last time, or straight into a folder you set once. Picking the log folder with Choose Folder… also lets this tab reopen it later without walking the tree again.
9. Export writes out every row matching your current filters, not just the rows on screen. Pick the format next to the button: .csv or .xlsx for a spreadsheet, .json/.ndjson for tooling (jq, scripts, Splunk/ELK ingest), or .log/.txt to get a filtered copy of the original raw entries in chronological order — which you can re-open in this tool or any log viewer. The file name records the filters you used. Everything is generated in the browser, so exports are as offline as the parsing is.
