MBS FORENSICS

MBS Log Analyzer — every source, correlated. No server, no network.

Load any mix of: auditLog / transactions CSV or XLSX exports, the APIMS log folder, and the local Serilog / Bakong Processor log folders. Everything is normalized to one event stream. Click a row → Correlate to pull every related record from all loaded sources into one timeline, linked by payRefNo↔sbiUniqueId, correlationId, handle/deviceId, RequestId, account and amount+time.

Add CSV / XLSX — one export per file, header row on row 1. Auto-detected as auditLog (has requestContent/responseContent) or transactions (has payRefNo / structuredDataRequest). For auditLog, raise SSMS "Maximum Characters Retrieved" to 2000000 or base64 the blobs; CSV beats XLSX (32,767-char cell cap truncates blobs). 
-- transactions (system of record)
SELECT t.ID, t.payRefNo, tt.shortCode AS transactionType, t.currency, t.amount,
       t.[from], t.[to], t.channelRefNo, t.requestTimestamp, t.responseTimestamp,
       t.success, t.cbsAuth, t.cbsRC, t.structuredDataRequest, t.structuredDataResponse
FROM [dbo].[transactions] t
LEFT JOIN [dbo].[transactionType] tt ON tt.ID = t.transactionType
WHERE t.requestTimestamp BETWEEN @Start AND @End ORDER BY t.requestTimestamp;
Add log folder — pick the folder holding APIMS routelog*.json (Node1/Node2), the MBS Logs/ dir (*__Ex_*/*__App_*), and/or the Bakong Processor logs/. Formats are auto-detected; drop several folders at once.

How the timeline links records: transactions payRefNo + transactionType → sbiUniqueId, matched as a substring in APIMS Data; auditLog envelope handle/deviceId; correlationId/traceIdentifier from additionalInfo; account numbers pulled from structuredData*; and a weak time-window pass for Serilog lines (which carry no correlation id at all — §17.1). Each row in the timeline shows the chain of keys that reached it from the seed — green for a shared identifier, amber with a ~ for an inferred match.

Timezone. The TIMEZONE control sets one thing used three ways: how CSV timestamps without an offset are parsed, what zone the table displays, and what zone the FROM/TO boxes are read in. They can no longer disagree.

Search. The box takes several keywords at once, in any order — khqr 412 0977000045 finds events containing all three, even though they live in different columns. It covers bodies, URIs, every column, plus status, level and source. Quote to keep words together: "insufficient balance". The box wraps and grows so the whole query stays readable, and with more than one keyword each is listed underneath with its own hit count — a typo shows as tmeout 0 rather than quietly emptying the table.

Several tabs at once. Name this tab in the bar at the top — the name, the folder it loaded and the event count go into the browser tab title and the favicon, so a row of these is readable at a glance. That bar also always says which folders this tab read and when, with the full file list one click away. copy range / paste range carry a time window between tabs and to the other analyzer.

Exports. export settings… sets the file name from a template ({label}, {from}, {rows}, …) and the destination: downloads, a Save as… dialog that opens where you saved last time, or straight into a folder you set once. Choosing the log folder with Add log folder… also lets this tab reopen it later in one click.

Time range. The FROM/TO boxes are plain text — paste a timestamp straight out of a row or a log line, or paste the whole line and it will find the timestamp. Any shape these sources use works: 2026-08-19 20:23:34.503, 2026-08-19T20:23:34.5033986+07:00, [2026-08-19 20:23:34.503], an epoch, or a partial like 2026-08-19 (the whole day), 20:23 (that minute on the last day loaded) or -2h (the last two hours of the data, not of right now). Arrow keys nudge by a minute — Shift for an hour, Alt for a second. Or just drag across the histogram: it stacks events by source so you can see where one source stops and the others carry on, and the drawer's ±30s around this button jumps the range to whatever you're looking at.
